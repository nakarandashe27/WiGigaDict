# M1 Step 17 clean-install runbook

## Статус

Этот runbook закрывает остаток Step 17: установка на **чистых** Windows 10 22H2 и Windows 11 x64 VM, первая CPU-диктовка, uninstall / repair / rollback. Всё остальное по этапу уже сделано — пакет собирается, воркер и подписанный каталог входят в установщик.

Прогон на машине разработчика ничего не доказывает: здесь уже стоят WebView2, VC++ runtime и Vulkan SDK. Именно их отсутствие и проверяется.

## Что берём в VM

Готовый комплект собирается в `artifacts/clean-install-kit/` (папка в `.gitignore`): установщик, скрипты, этот runbook, `ggml-base.bin`, пакет `WiGigaDict-spike.msix` с сертификатом `spike.cer` для второй части и `SHA256SUMS.txt`. Рядом лежит `artifacts/clean-install-kit.zip` (137 МБ) — его и закидывать в VM. Распаковать и сверить:

```powershell
Get-Content .\SHA256SUMS.txt | ForEach-Object { $parts = $_ -split "  ", 2; $actual = (Get-FileHash $parts[1] -Algorithm SHA256).Hash.ToLowerInvariant(); "{0} {1}" -f $(if ($actual -eq $parts[0]) { "OK" } else { "BAD" }), $parts[1] }
```

Собрать комплект заново после любой пересборки установщика: он несёт `catalog.json` внутри себя, и старый пакет повезёт в VM устаревший каталог.

Состав, если собирать вручную:

- `scripts\verify-clean-install.ps1`;
- `target\release\bundle\nsis\WiGigaDict_0.0.1_x64-setup.exe`;
- ggml-модель для CPU-прогона, например `ggml-base.bin` (142 МБ) — иначе её придётся ставить в VM через каталог по сети;
- при проверке rollback — установщик предыдущей версии.

Речевой образец записывать не нужно: скрипт синтезирует фразу встроенным в Windows SAPI (16 kHz mono s16) и сверяет с ней распознанное. Белый шум для этого не годится — на нём whisper галлюцинирует. Свой файл можно подставить ключом `-SpeechWav`, тогда проверяется только непустой результат.

Ничего из репозитория, тулчейна и Vulkan SDK в VM не ставить: VM должна остаться чистой.

## Подготовка VM

1. Свежая Windows 10 22H2 x64 и отдельно Windows 11 x64, обе после установки обновлений, но **без** установки Edge WebView2 Runtime вручную и без Visual Studio.
2. Обычная non-elevated учётная запись.
3. Снимок (checkpoint) до первого запуска — прогон повторяется с чистого состояния для каждой ОС.
4. Микрофон проброшен в VM, иначе ручная диктовка невозможна.
5. Сеть: если установщик тянет WebView2 bootstrapper, она нужна на шаге установки. Ручную диктовку выполнять с отключённой сетью.

## Прогон

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\verify-clean-install.ps1 -Installer .\WiGigaDict_0.0.1_x64-setup.exe -ModelPath .\ggml-base.bin
```

Скрипт пишет `clean-install-report-<дата>.md` рядом с собой и возвращает ненулевой код при любом FAIL. Проверки:

1. Снимок среды: не administrator, x64, версия WebView2, наличие VC++ runtime и Vulkan loader **до** установки, отсутствие Python в PATH, свободное место, отсутствие прежней установки.
2. Тихая установка `/S`: код возврата, время, полный состав `%LOCALAPPDATA%\WiGigaDict` (desktop, sidecar, worker, `catalog.json`, `catalog.sig`, `uninstall.exe`), отсутствие записи в `Program Files`.
3. Первый запуск и soak 30 секунд: процесс жив, `storage` создан, пиковый working set.
4. CPU-распознавание воркером на профиле `cpu-t16` по синтезированной фразе: узнано должно быть не меньше 60% её слов. В отчёт идут модель, голос, объём текста, `inference_ms` и доля узнанных слов; содержимое не пишется. Модель берётся из `-ModelPath`, иначе самая маленькая из уже установленных приложением. Воркер печатает диагностику whisper.cpp в stderr — это нормально.
5. Деинсталляция `/S`: бинарники удалены, `storage`, `audio`, `logs`, `installed`, `quarantine` сохранены пофайлово.
6. Repair: повторная установка поверх данных, данные на месте, приложение запускается.
7. Rollback: при `-PreviousInstaller` — деинсталляция, установка предыдущей версии, запуск.

Полезные ключи: `-SkipUninstallCycle` (только установка и запуск), `-ModelPath`, `-SpeechWav`, `-PreviousInstaller`, `-Report`, `-SelfTest` (проверка логики самого скрипта, ничего не устанавливает).

Проверено на машине разработчика: SAPI-голос Irina, `ggml-base.bin`, профиль `cpu-t16` — узнано 0,89 слов фразы за 6 с inference.

## Ручные шаги

Скрипт помечает их `MANUAL` и оставляет строки пустыми — заполнить в отчёте руками:

1. **Модель.** Экран «Модели»: загрузить из каталога либо импортировать из папки. Записать, какой путь использован; каталог без сети недоступен и должен честно об этом сказать.
2. **Первая микрофонная диктовка на CPU.** Hotkey, речь, отпустить. Overlay проходит Recording → Processing → Delivered, текст вставлен. Это и есть критерий готовности этапа: автоматический шаг 4 доказывает только тракт распознавания, но не микрофон, оверлей и вставку.
3. **Вставка.** Блокнот и VS Code/Codex.
4. **Внешний вид.** Оверлей не забирает фокус, tray работает, диалоги на русском.

Содержимое диктовки в отчёт не переносить: фиксируется факт, а не текст.

## Часть 2: спайк MSIX (BL-049, не Step 17)

Отдельный вопрос, который дешевле проверить в той же виртуалке: годится ли раздача через Microsoft Store. Это единственный путь, где предупреждение SmartScreen не показывается вовсе — Microsoft переподписывает пакет сам. Разбор целиком: [подпись и SmartScreen](../../context/architecture/05-стек/исследования/2026-09-02-authenticode-и-smartscreen.md).

**Только в одноразовой VM.** Скрипт ставит тестовый сертификат в машинное хранилище доверия и требует запуска **от администратора** — на рабочей машине так делать не нужно. Сертификат одноразовый: в реальной раздаче пакет подписывает Microsoft при публикации.

Порядок: сначала часть 1 до конца, затем деинсталлировать обычную версию (общий на пользователя single-instance mutex не даст двум версиям работать одновременно), затем:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .erify-msix-spike.ps1 -Package .\WiGigaDict-spike.msix -Certificate .\spike.cer
```

Автоматически: установка пакета, состав внутри, запуск из контейнера с soak 30 с, **куда легли данные** — в обычный `%LOCALAPPDATA%\WiGigaDict` или в приватный контейнер пакета, — удаление пакета и судьба данных после него.

Вручную, и это главное ради чего спайк затевался: глобальный хоткей, доступ к микрофону, вставка текста в чужое окно, поведение оверлея и запуск sidecar с воркером из пакета. Именно эти возможности в контейнере ограничены, и пока они не проверены, Store обещать нельзя.

Провал любой из ручных проверок — не катастрофа, а ответ: значит, путь Store закрыт и остаётся открытие исходников со SignPath.

## Критерий закрытия Step 17

Обе VM: 0 FAIL в отчёте части 1, ручная CPU-диктовка прошла, uninstall/repair/rollback зелёные. Часть 2 к Step 17 не относится и на его закрытие не влияет. Оба отчёта кладутся в `logs/`, роадмап переводится в `[x]` со ссылкой на них.

Провал фиксируется как есть: чинить код, а не отчёт.
