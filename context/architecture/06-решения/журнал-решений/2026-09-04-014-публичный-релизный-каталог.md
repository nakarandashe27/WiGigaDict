# ADR-014: подписанный каталог как публичный release input

Дата: 2026-09-04

Статус: принято

## Контекст

`catalog.json` и `catalog.sig` исключались из Git, хотя Tauri bundle объявлял их обязательными resources. Release workflow на чистом runner не мог получить эти файлы: приватный ключ намеренно хранится offline, а CI располагал только публичным ключом и не мог заново подписать каталог.

## Решение

- Версионировать подписанные `catalog.json` и `catalog.sig`: это публичные данные, которые приложение всё равно распространяет внутри installer и через GitHub Release.
- Закрепить публичный Ed25519-ключ непосредственно в CI/release workflow. Публичный ключ не является секретом и должен воспроизводимо соответствовать закоммиченному каталогу.
- Приватный ключ никогда не передавать GitHub Actions и продолжать хранить вне working tree.
- При изменении каталога владелец подписывает его offline, проверяет штатным verifier и коммитит новую пару каталога и подписи.

## Последствия

Чистый checkout получает все входы для воспроизводимой сборки installer. Компрометация репозитория сама по себе не позволяет подписать новый доверенный каталог без приватного ключа. Review изменения `catalog.json`/`catalog.sig` становится обязательной частью release-коммита.
