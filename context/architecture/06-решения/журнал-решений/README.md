# Журнал архитектурных решений

Здесь фиксируются только значимые изменения уже принятой архитектуры: смена стека, модели данных, trust boundary, модуля или release contract. Текущее целевое состояние всегда обновляется в соответствующем файле `context/architecture/`; ADR сохраняет причину и дату изменения.

## Именование

`YYYY-MM-DD-NNN-краткое-решение.md`, например `2026-08-21-001-смена-asr-adapter.md`.

## Шаблон ADR

```markdown
# ADR-NNN: Краткое решение

- Дата: YYYY-MM-DD
- Статус: proposed | accepted | superseded | rejected
- Заменяет: —

## Контекст

Какой факт, gate или ограничение заставило пересмотреть решение.

## Решение

Что именно меняется в целевой архитектуре.

## Последствия

Плюсы, минусы, миграция, тесты и документы, которые синхронизированы.

## Затронутые документы

- `context/architecture/...`
```

Мелкое уточнение текста, порога после benchmark или implementation detail без изменения границы не требует ADR.
