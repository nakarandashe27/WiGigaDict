# ADR-008: CPU retry при падении GPU-worker и прозрачные исходы доставки

- **Дата:** 2026-08-27
- **Статус:** принято для personal alpha
- **Заменяет:** уточняет пункт 2 ADR-006 (запрет скрытого переключения профиля)

## Контекст

Owner-ledger (`delivery_operation`/`asr_attempt` за 2026-08-26/27) показал три доминирующих реальных исхода:

1. 12 сессий закончились `worker_exited`: Vulkan-worker падает, когда GPU занята другим приложением (генерация изображений держит VRAM). Retry шёл тем же профилем `gpu` и падал идентично; при свободной GPU тот же worker и тот же WAV отрабатывают с exit 0. Цель вставки не влияет: падения зафиксированы при фокусе на ChatGPT, browser, Comfy Desktop и собственном окне приложения.
2. 31 операция доставки завершилась `invalid_insertion_text`, и во всех случаях транскрипт был пустой строкой: «нечего вставлять» отображалось как ошибка доставки.
3. Все успешные вставки (`transport_only`) показывались владельцу как «Вставка не подтверждена», хотя текст фактически дошёл во все проверенные цели.

Дополнительно stderr упавшего worker читался (bounded 16 KiB) и выбрасывался — причина `worker_exited` не сохранялась нигде.

## Решение

1. Retry-generation (`lease_generation > 1`) никогда не переиспользует профиль `gpu`: `build_request` явно переводит его в замороженный `cpu-t16` из ADR-006. Переключение не скрытое: overlay публикует reason `processing_cpu_fallback` («GPU занята — обработка на CPU»), а метрики попытки фиксируют фактический профиль и `worker_restarts`. Первая попытка сессии всегда остаётся `gpu`; запрет ADR-006 на скрытое переключение внутри session сохраняется — переключение объявляется владельцу и попадает в ledger.
2. Пустой (или whitespace-only) транскрипт получает собственный терминальный код `empty_transcript` вместо `invalid_insertion_text`. Ретрай для него бессмыслен; overlay сообщает «Распознан пустой текст». Evidence-модель не меняется: операция по-прежнему завершается `uncertain` с immutable attempt.
3. `DeliveryReceipt` дополнен `error_code`, и overlay различает под-случаи `uncertain`: `empty_transcript`, `delivery_transport_only` («Текст вставлен (без подтверждения)») и прочие `delivery_unconfirmed`. Порог для статуса `delivered` не ослабляется: он всё так же требует `target_ack` или certified transport.
4. stderr сайдкара направляется в `%LOCALAPPDATA%\WiGigaDict\logs\asr-sidecar.log` (append), а engine при `worker_exited` пишет туда timestamp, exit status и bounded stderr tail worker'а. Content-free diagnostics не меняются; это owner-local crash detail вне export-конвейера.

## Последствия

Диктовка при занятой GPU деградирует в медленный CPU-проход вместо терминальной ошибки (p95 CPU из ADR-006 — до ~57 s при timeout 120 s; длинные диктовки могут упереться в timeout — известное ограничение). Причины падений worker становятся диагностируемыми по локальному логу. Registry совместимости остаётся пустым; изменение не создаёт новых путей к `delivered`.
