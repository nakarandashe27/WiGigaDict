# ADR-012: ASR worker поставляется с приложением, а не внутри model package

- Дата: 2026-08-31
- Статус: accepted
- Заменяет: уточняет [ADR-011](2026-08-31-011-подписанный-каталог-моделей.md) п.8

## Контекст

`ModelManager` скачивает каждый файл, перечисленный в манифесте пакета, и для каждого требует `download_uri`. Замороженный пакет ADR-006 содержит два файла: веса `ggml-large-v3-turbo-q5_0.bin` (547 МБ) и программу `wigigadict-asr-worker.exe` (54 МБ), которая эти веса читает. Воркер собирается из `tools/asr-benchmark` этого репозитория и в bundle приложения не входит: рядом с приложением кладётся только sidecar (1,1 МБ).

Поэтому запись каталога была принципиально неполна: веса скачать можно, программу — неоткуда. Тул подписи это ловил и отказывался подписывать каталог, то есть каталог не мог заработать ни у одного пользователя.

Рассматривались два варианта:

- **A.** Опубликовать воркер релизным ассетом и качать его как обычный файл пакета.
- **B.** Поставлять воркер вместе с приложением, оставив в пакете только веса.

## Решение

Принят вариант **B**.

1. Воркер — часть приложения, а не часть модели: он говорит на CLI-контракте конкретной сборки приложения. Sidecar уже поставляется именно так.
2. Вариант A означал бы скачивание и хранение одного и того же 54-МБ бинаря по копии на каждую модель (для каталога из четырёх — 218 МБ дублей) и риск расхождения версий воркера и приложения.
3. Путь воркера ищется по списку кандидатов, повторяющему логику sidecar: переменная `WIGIGADICT_ASR_WORKER`, каталог рядом с исполняемым файлом, его `resources`/`binaries`, затем `binaries` в дереве исходников. Имя берётся из константы приложения, а не из манифеста, поэтому запись каталога не может попросить запустить произвольный бинарь.
4. Пакет, который **несёт свой воркер**, продолжает его использовать: замороженный пакет ADR-006 формирует байт-идентичные запросы, и baseline Step 16 не сдвигается.
5. Целостность воркера переходит из per-package SHA-256 в подпись установщика — тот же уровень доверия, что у sidecar и у самого приложения. Ожидаемый хэш вычисляется один раз за процесс и доказывает, что бинарь не менялся в течение сессии, а не что он именно тот, который мы выпустили.
6. Тул подписи требует, чтобы `worker_path` либо входил в скачиваемые файлы, либо в точности совпадал с именем поставляемого воркера.

## Последствия

Каталог перестал быть заблокированным: `catalog.source.json` из четырёх записей подписывается, приложение показывает их рядом с установленной моделью, фильтр по языку получает данные.

Упаковка воркера в установщик остаётся Step 17 и **этим ADR не выполнена**. В `externalBin` он сознательно не добавлен: CI выполняет `npm run tauri:build`, а собрать воркер на раннере нельзя без Vulkan SDK, и отсутствующий файл ломал бы сборку. До Step 17 воркер кладётся в `apps/desktop/src-tauri/binaries/` тем же способом, что и sidecar (`binaries/*.exe` в `.gitignore`).

Модель угроз не меняется: сетевой клиент остаётся единственным в model manager, воркер по-прежнему запускается только с путями внутри managed root и проверяется по хэшу перед запуском.
