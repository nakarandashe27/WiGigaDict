# Безопасность WiGigaDict

## Принятая модель защиты

Personal MVP — локальное desktop-приложение без аккаунта, backend и обязательной сети. Доверенная identity — текущая интерактивная Windows-сессия; WiGigaDict работает без elevation и не создаёт собственную систему паролей.

Для MVP принят baseline:

- managed data хранится в per-user каталоге `%LOCALAPPDATA%\WiGigaDict\`; runtime ставит protected inheritable DACL только для текущего владельца, `SYSTEM` и `Administrators`, отклоняет reparse path/неизвестный allow ACE и не даёт доступ `Everyone` или другим обычным учётным записям;
- прикладное шифрование SQLite/PCM не входит в MVP; защита выключенного диска делегируется Windows/BitLocker;
- администратор, `SYSTEM` и вредоносный процесс, уже исполняющийся от имени текущего пользователя, находятся вне защищаемой границы и способны прочитать или изменить локальные данные;
- основной результат защищается прежде всего от утечки по сети, случайного доступа другого обычного Windows-пользователя, повреждения при crash и несанкционированных действий WebView/sidecar.

Это не формулировка «данные полностью защищены». На устройстве без шифрования диска plaintext PCM, SQLite/WAL и экспортированные bundles могут быть извлечены при физическом доступе.

## Активы и личные данные

| Актив | Где находится | Чувствительность | Срок и удаление | Защита MVP |
|---|---|---|---|---|
| `.part`/final PCM | Managed audio storage | Высокая: голос и содержание | После durable raw удаляется по safe-point; при failure/uncertain — до явного resolution/delete | Per-user ACL, случайные непрогнозируемые имена, запрет внешних путей, hash/reconciliation |
| Raw/cleaned transcript | SQLite + WAL/SHM | Высокая: рабочие задачи, код, имена | Delivered — 15 дней; unresolved — до решения; pinned — бессрочно | Per-user ACL, immutable versions, prepared statements, no remote sync |
| Glossary и профили | SQLite | Средняя/высокая: термины и персональные названия | До явного изменения/удаления | Versioned records, input limits, не используется как команда |
| Target/process metadata | SQLite events/diagnostics | Средняя: раскрывает используемые приложения | Вместе с session либо rolling diagnostic policy | Allowlist без title/target content и без полного пользовательского пути |
| Технические логи | Rolling JSONL | Низкая/средняя | Alpha default: 30 дней или 100 MiB, что наступит раньше | Allowlist, без audio/transcript/clipboard content, redaction tests |
| Diagnostic bundle | Выбранный пользователем путь | Зависит от preview и явных вложений | После export находится вне managed retention; удаляет владелец | Manifest + preview; текст/audio только отдельным явным действием |
| Model/app packages | Managed packages/installer | Не персональные, но исполняемые/влияют на output | Пока установлены или нужны rollback | Signed manifest, checksum, version floor, health/probe gate |
| Clipboard snapshot | Память процесса/Windows clipboard | Может содержать чужой секрет | Только на время paste/restore; не журналируется | Не сохраняется в SQLite/log; best-effort restore с отдельным error |
| Local Notetaker source | Внешний путь пользователя | Высокая: запись встречи; приложению не принадлежит | Никогда не удаляется/изменяется/копируется без отдельного opt-in | Snapshot path/size/mtime/hash, read-only access, source-change gate; полный path не логируется |
| Yandex public URL и download metadata | SQLite только у non-terminal ingress job | Высокая: public capability token/имя ресурса | Удаляются после durable PCM; direct temporary href не постоянный artifact | Capability off by default, per-user ACL, redaction, bounded lifetime |
| Downloaded Yandex container | Managed `.part`/final storage | Высокая: пользовательское media | Удаляется после durable PCM; persistent original copy отсутствует в v1 | Dual size cap, reservation, same-volume durable commit, hash/reconciliation |
| Notetaker PCM chunks | Managed media storage | Высокая: нормализованный голос/содержание | После completed/incomplete commit; retained PCM только explicit opt-in | Per-user ACL, commit/hash/checkpoints, явный storage accounting |
| Notetaker transcript versions | SQLite + WAL/SHM | Высокая: встречи/записи | До явного удаления job | Immutable raw/derived versions, no remote sync, cascade inventory |

Полный реестр физических копий перед release обязан включать SQLite, WAL, SHM, PCM, `.part`, quarantine, rolling logs, crash dumps и exported bundles. Удаление строки из history не считается доказательством удаления всех копий.

## Секреты и ключи

В runtime personal MVP нет API keys, cloud tokens, паролей или refresh tokens.

- Private code-signing/update keys никогда не входят в source, installer, runtime config или логи. В CI они доступны только как secret/environment input на время signing; для public release предпочтителен hardware-backed или отдельный signing service.
- Public verification keys и key IDs не являются секретами: они pin-ятся в приложении и signed manifest.
- Если будущая функция потребует локальный секрет, он хранится не в SQLite/env-файле, а через Windows DPAPI, привязанный к текущему пользователю. Microsoft указывает, что без machine-wide flag данные обычно расшифровывает пользователь с теми же logon credentials на том же компьютере: [CryptProtectData](https://learn.microsoft.com/en-us/windows/win32/api/dpapi/nf-dpapi-cryptprotectdata).
- `.env`, credentials и private keys запрещены в release artifact; CI выполняет secret scan до сборки.

## Вход и жизненный цикл сессии

Отдельного login нет. Пользователь «входит» в WiGigaDict, войдя в Windows. App session живёт внутри одного desktop process generation:

1. single-instance mutex не допускает второй shell того же пользователя;
2. startup generation id отделяет события до/после crash/restart;
3. разрешение на запись возникает только из физического hotkey/явного UI action и ограничено одной `session_id`;
4. lock/sign-out/shutdown запрещает новые recordings, останавливает capture и запускает durable finalize/recovery;
5. app restart не возобновляет микрофон или insertion автоматически, но восстанавливает durable очередь и unresolved results.

Смена Windows-пользователя создаёт независимое per-user data directory. B2B-аккаунт или общая машинная база не добавляются поверх этой модели автоматически.

## Проверка прав и изоляция компонентов

Решение «можно ли» принимается в Rust shell на каждом privileged command; состояние кнопки в React не является авторизацией.

- Каждая команда проверяет caller window label, capability, schema/length, `session_id`, expected `state_version`, managed path и policy из [матрицы прав](../02-ядро/права-доступа.md).
- Main settings/history window получает только нужные команды. Overlay получает recording state/render events, но не model install, arbitrary filesystem/shell, network, destructive history или updater permissions.
- Remote URLs/iframes не получают Tauri API; production WebView загружает только bundled assets, имеет строгий CSP и не допускает remote navigation.
- Tauri предупреждает, что capabilities разных наборов для одного WebView объединяются, а зарегистрированные custom commands требуют отдельного ограничения. Поэтому capability files перечисляются явно в build config, а Rust command allowlist проверяется тестом: [Tauri capabilities](https://v2.tauri.app/security/capabilities/).
- ASR sidecar — недоверенный вычислитель: только inherited stdin/stdout, никакого listening port, UI handle, shell или произвольного filesystem API. Shell передаёт managed artifact id/path/hash; worker проверяет protocol version, message size, path containment и hash.
- Windows insertion всегда повторно проверяет HWND/process identity/integrity. Elevated target, focus mismatch или недостаточный evidence заканчиваются `uncertain`, а не обходом boundary.

## Сеть и недоверенный ввод

Основной pipeline обязан проходить offline test при запрещённой исходящей сети. Сетевые клиенты физически изолированы в model/update manager и вызываются только явным действием/opt-in.

- Model/update URL берётся только из подписанного manifest или явного import; redirect, scheme, final host, размер и content type валидируются.
- Download идёт по HTTPS в `.part`; install запрещён до signature/checksum, полного manifest, path traversal check, compatibility probe и atomic commit.
- Imported config/model/archive считается недоверенным: canonical path остаётся внутри managed root; symlink/reparse-point escape и archive traversal отклоняются.
- ASR/cleanup text, glossary и filename никогда не интерпретируются как shell, SQL, HTML или команда target-приложения.
- SQL выполняется prepared statements; JSON/NDJSON имеет versioned schema, предел размера и reject unknown critical fields.

## Опциональный Yandex ingress

Notetaker M2 добавляет единственную допустимую передачу user-supplied URL наружу. Это не cloud processing, но самостоятельная privacy/network boundary:

- `yandex_import_enabled=false` по умолчанию; первое включение требует disclosure, остаётся отзывным и не запускает background traffic;
- каждый import начинается только кнопкой «Скачать и распознать»; WebView не получает network capability/client;
- v1 принимает один public downloadable file через официальный API, без OAuth/private resources/folders/passwords/no-download bypass;
- URL canonicalization выполняется до запроса; scheme только HTTPS; redirect count bounded; каждый resolved/final address проверяется против loopback/private/link-local/unspecified/multicast и DNS rebinding;
- credentials/cookies/user headers не переносятся на redirect; response filename/content type не доверены и не определяют parser policy;
- source size ≤2 GiB проверяется по `Content-Length`, если он есть, и по фактически принятым bytes всегда; reservation включает container + PCM + 20%; oversize `.part` не становится final;
- temporary href обновляется через официальный API при expiry. Resume использует валидированный Range/ETag metadata; если сервер не подтверждает resume, partial отбрасывается и download начинается заново;
- public URL/direct href/transcript/path не попадают в production logs/diagnostic bundle. После durable PCM URL metadata/container удаляются.

Security acceptance включает malicious redirect chain, DNS rebinding между resolve/connect, content-length mismatch, chunked oversize, expiry, no-download, disabled capability after restart и low-disk resume. Решение: [ADR-002](../06-решения/журнал-решений/2026-08-21-002-опциональный-yandex-ingress.md).

Перед M2 release отдельно сверяются актуальные API terms: официальный Yandex Cloud пример документирует anonymous public-resource download, но общие условия Disk API упоминают регистрацию/OAuth. Если anonymous desktop use нельзя подтвердить без OAuth, capability остаётся невыпущенной; OAuth/private scope в v1 не добавляется.

## Поверхность атаки и attacker stories

| Источник | Реалистичная история | Главный контроль |
|---|---|---|
| Compromised mirror/DNS/release account | Пользователь получает подменённый installer, sidecar или модель, которая исполняет код либо портит transcript | Pinned root key, signed manifest, Authenticode, checksum, version floor, probe и rollback |
| Compromised/ошибочный WebView | Скрипт пытается читать файлы, запускать shell, устанавливать модель или удалять history | Bundled-only UI, CSP, per-window capabilities, Rust-side authorization и managed DTO |
| Malformed/malicious model или archive | Package делает traversal/reparse escape, исчерпывает диск или ломает runtime parser | Size/free-space preflight, safe extraction, managed root, signature/hash, process isolation |
| Crashed/compromised ASR sidecar | Worker отправляет oversized/invalid IPC, читает чужой path или пытается зависнуть | Inherited stdio only, message/path/hash checks, one lease, watchdog, kill/restart, no shell/network capability |
| Adversarial/нестабильный target app | Окно меняет focus/integrity или принимает только часть synthetic input | Immutable target snapshot, revalidation, certified evidence, no elevated insertion, recovery |
| Другой обычный Windows user | Пытается прочитать managed plaintext другого профиля | Per-user install/data ACL и отсутствие shared machine store |
| Повреждение диска/crash/power loss | DB и PCM расходятся, retention удаляет последнюю копию | Two-storage commit/reconciliation, hashes, quarantine, immutable raw, fault injection |
| Compromised developer/CI | В release попадает чужой dependency, secret или подписанный вредоносный artifact | Locked dependencies, protected/tagged release, isolated signing key, SBOM/provenance, two-person gate для public release |
| Malicious local media/container | Parser exploit, decompression bomb, ложные duration/stream metadata или зависший decoder | Supervised exact-pinned FFmpeg, probe/decode limits, process timeout/cancel, tested format allowlist, no source mutation |
| Malicious/expired public URL | SSRF, redirect в локальную сеть, oversize stream или утечка public token в log | Узкая Yandex capability, official API, per-hop address validation, dual byte cap, redaction и bounded URL retention |

Нереалистичные для current MVP web-классы — CSRF, tenant escape, password reset takeover и public API abuse: аккаунтов, cookies, multi-tenancy и HTTP server нет. Они становятся применимыми при появлении control plane и требуют новой модели угроз.

## Журнал действий

Content-free audit trail записывает UTC-время, component/build fingerprint, process generation, `session_id?`, correlation/sequence, actor (`owner/system/windows`), action, reason code, from/to state, result и `missing_source`. Записываются:

- старт/stop/cancel recording и device failure;
- storage prepare/finalize/reconciliation/corruption/delete;
- ASR lease/start/timeout/crash/retry/result без transcript;
- cleanup policy/version/result без текста;
- target check, insertion method/evidence/outcome без содержимого;
- config, retention, pin/resolve/delete, model install/remove, update и diagnostic export;
- Notetaker preflight/stage/pause/cancel/checkpoint/cleanup/export без source path, URL, audio или transcript;
- Yandex capability enable/revoke, download byte counters/retry/error class без URL/direct href;
- security rejection: invalid path/schema/signature/capability/integrity/rate limit.

Не записываются audio, transcript, glossary values, clipboard content, window title, command line, полный пользовательский path, environment и secret. Diagnostic export сначала показывает manifest/redaction preview; создание и отправка наружу — разные действия.

✅ **Step 15:** этот контракт реализован typed allowlist NDJSON-схемой с bounded event/metadata, monotonic sequence, crash-tail recovery и rolling retention. Bundle повторно валидирует каждую запись, fail-closed отклоняет неизвестную/future schema и reparse point, показывает SHA-256 preview и требует точное подтверждение перед atomic no-overwrite export. Marker/redaction tests и deny-all offline harness входят в канонический quality gate; сеть остаётся только у отдельного explicit model manager.

## Лимиты и защита от злоупотребления

У WiGigaDict нет HTTP endpoints, но локальные границы всё равно ограничены:

| Граница | Alpha limit/policy | Поведение при превышении |
|---|---|---|
| Recording | 1 active session; 32 MiB PCM/session | Durable finalize/recovery, без truncation |
| Pending ASR | 20 sessions; 256 MiB; 1 lease; ≥1 GiB free after reservation | Отказ до включения микрофона, принятые данные сохраняются |
| Hotkey | Debounce, auto-repeat ignored, одна physical press generation | Duplicate event ignored и журналируется агрегированно |
| IPC | Одна leased attempt; line/message hard cap 2 MiB; transcript payload hard cap 1 MiB UTF-8 | Worker/message rejected, session остаётся recoverable |
| Model install | Один active job на package/version; free-space preflight ≥ package staging + installed size + 1 GiB reserve | Download не стартует/приостанавливается |
| Diagnostic logs | 30 дней или 100 MiB | Rolling deletion только content-free logs; session artifacts не затрагиваются |
| Diagnostic bundle | Default cap 100 MiB без явных user attachments | Export останавливается с manifest missing/oversize |
| Update check | Только explicit/opt-in; одна single-flight check | Duplicate request coalesced; active version не меняется |
| Notetaker source | ≤2 GiB и ≤4 часа; probe до decode | Job не принимается; source не изменяется |
| Notetaker queue | 1 active decode/ASR + 2 waiting; Dictation absolute priority | Третья waiting отклоняется; Notetaker yields на safe boundary |
| Notetaker disk | Local: PCM + 20%; Yandex: container + PCM + 20% на каждый accepted job | Admission/download pause до записи; committed transcript/checkpoints сохраняются |
| Yandex redirects/download | HTTPS, bounded hops, dual size cap, no private/link-local | Request/download отклоняется; `.part` не становится final |

Числа message/bundle/log limits являются alpha safety defaults и могут меняться после теста, но никогда не становятся unbounded.

## Цепочка поставки и обновление

- Dependencies exact-pinned/locked; release gate строит SBOM, license inventory, vulnerability report и provenance из tagged commit на Windows runner.
- App, sidecar и model package имеют единый signed release manifest: artifact hashes, compatibility ABI, key id, version floor, expiry/revocation metadata и rollback target.
- Tauri updater signature и Windows Authenticode решают разные задачи; public installer требует оба контроля. Personal alpha до signing устанавливается вручную только из проверенного локального build и не включает silent updater.
- Root public key pin-ится в приложении; private root хранится offline. Online signing key ротируется; downgrade и неизвестный/revoked key отклоняются.
- Каталог доступных моделей подписан тем же Ed25519-ключом и проверяется как открепленная подпись над `catalog.json`. Запись каталога несёт точные байты подписанного package manifest, который `ModelManager` проверяет повторно перед установкой, поэтому подменённый каталог не может подсунуть другой пакет. Беззнакового режима нет: без pin-нутого публичного ключа каталог просто недоступен, а установка невозможна ([ADR-011](../06-решения/журнал-решений/2026-08-31-011-подписанный-каталог-моделей.md)).
- Model package проходит license/notice audit отдельно от runtime. MIT-лицензия текущих [whisper.cpp](https://github.com/ggml-org/whisper.cpp/blob/master/LICENSE), [GigaAM](https://github.com/salute-developers/GigaAM) и [ONNX Runtime](https://github.com/microsoft/onnxruntime) не отменяет проверку конкретных весов, bundled DLL и third-party notices.

## Проверка «опасной тройки»

Пара читающего/действующего AI-агента не нужна:

1. доступ к личным данным есть — audio/transcripts обрабатываются локально;
2. контакт с недоверенным содержимым ограничен данными, которые не становятся инструкциями;
3. возможности автономно отправить audio/transcript наружу нет: cloud ASR/API/email/telemetry запрещены. M2 Yandex capability отправляет только явно введённый public URL Яндексу и скачивает выбранный source после отдельной команды; diagnostic send остаётся отдельным действием владельца.

Отрезаны две ноги из трёх: нет instruction-following агента и нет autonomous exfiltration tool. Если появится prompt optimization с инструментами или облачная отправка, этот вывод аннулируется и threat model строится заново до реализации.

## B2B gate — не часть personal MVP

До пилота в российской организации обязательны отдельные решения и реализация:

- роли как минимум `organization owner`, `security admin`, `deployment admin`, `auditor`, `user`, `scoped support`, без универсального admin;
- корпоративный вход через выбранный российский/корпоративный IdP, lifecycle joiner/mover/leaver и offline policy cache;
- централизованный tamper-evident audit export без audio/transcript по умолчанию;
- экспорт пользовательских данных, soft delete, legal hold и подтверждаемое удаление по запросу;
- signed enterprise policy для запрета сети, моделей, update channels и diagnostic export;
- уведомления внешним SIEM/MDM только по allowlist и с retry/dead-letter policy;
- tenant/device/request limits, abuse controls и status page для любого появившегося control plane;
- data residency/legal review, договоры, счета с НДС, ККТ/чеки и incident-response channel.

Personal SQLite не превращается в multi-tenant store; корпоративный control plane проектируется отдельной архитектурной фазой.

## Release gates безопасности

Personal alpha запрещена, пока не пройдены:

1. ACL/managed-path test под двумя Windows users и проверка отсутствия broad ACL.
2. Offline deny-all test: golden dictation не создаёт DNS/socket/HTTP traffic.
3. Capability/CSP test: overlay/compromised WebView не вызывает filesystem, shell, network, updater, model install или delete commands.
4. IPC fuzz/path test: oversized/malformed NDJSON, traversal, reparse point и чужой artifact не покидают managed boundary и не crash-ят shell.
5. Supply-chain test: неверная/revoked signature, checksum, downgrade и incompatible model остаются `not_ready`.
6. Redaction test: logs/bundle не содержат контрольные audio/text/glossary/clipboard/path secrets.
7. Retention/delete test после restart проверяет SQLite/WAL/SHM, PCM, `.part`, quarantine и managed exports.
8. Win32 privilege/evidence matrix не допускает insertion в elevated/changed target и false `delivered`.
9. Fault/load tests трёх killer contracts из [premortem](риски-архитектуры.md) сохраняют все принятые результаты.

✅ **Personal-alpha security gate / Step 15:** накопленные ACL/managed-path, capability/CSP, IPC size/schema, signed model/downgrade, retention/physical-copy и Win32 evidence suites объединены с новым offline deny-all, marker redaction и diagnostic export audit. Dependency policy, licenses и CycloneDX SBOM проверены отдельным supply-chain gate без исключений для production dependencies.

Перед выпуском Notetaker M2 дополнительно обязательны:

10. FFmpeg build/license/dependency/media-matrix gate из [research spike](../05-стек/исследования/2026-08-21-ffmpeg-lgpl-build-spike.md).
11. Local-file offline test и Yandex SSRF/redirect/oversize/expiry/capability-revoke matrix.
12. 4-hour resource/crash/preemption soak и physical-copy cleanup inventory для completed/incomplete/delete.
13. First-use notice/version, persistent reminder и network-stage copy tests без ложного privacy promise.

## Калибровка тяжести

- **Critical:** путь к удалённому/поставочному выполнению произвольного кода в подписанном release; компрометация signing root; скрытая массовая отправка audio/transcripts наружу; update/model package, позволяющий code execution до проверки подписи.
- **High:** чтение чужих диктовок другим обычным Windows user из-за broad ACL; WebView вызывает privileged Rust command вне capability; insertion обходит integrity boundary; автоматическое удаление последней recoverable копии; подписанный downgrade на известный уязвимый runtime.
- **Medium:** локальный unprivileged DoS в пределах текущего пользователя, обходящий queue/disk/log limit без потери уже принятых результатов; утечка process metadata/путей в diagnostic bundle; clipboard не восстановлен, но исходный текст сохранён и ошибка видима.
- **Low:** раскрытие build/model versions без персональных данных; временная деградация overlay/ASR с корректным recovery; действие, требующее явного подтверждения владельца и не пересекающее privilege/privacy boundary.

Доступ администратора, `SYSTEM`, malware текущего пользователя и чтение выключенного незашифрованного диска — accepted residual risks варианта 1, а не уязвимости WiGigaDict сами по себе. Они становятся reportable, если приложение расширяет ACL, передаёт данные другому пользователю/процессу, создаёт скрытую сетевую копию или обещает защиту, которой нет.
