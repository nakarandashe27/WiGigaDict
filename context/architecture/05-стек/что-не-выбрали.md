# Что сознательно не выбрано

Решения ниже отвергнуты для personal MVP, а не навсегда. Возврат к ним требует конкретного failed gate или новой продуктовой границы — не общего аргумента «может пригодиться».

## Основа приложения

### Полный fork AudioBud/Handy

Не выбран как foundation. AudioBud ближе всех к нужному Windows workflow и подтверждает жизнеспособность Tauri/Rust/React + CPAL + SQLite + local ASR, поэтому остаётся главным источником ограниченных модулей и тестовых идей. Но текущий Cargo graph включает fork Tauri runtime, несколько git dependencies и гораздо более широкий model/feature scope; глубокий lineage/security/license audit ещё не завершён. [AudioBud Cargo.toml](https://github.com/jamditis/audiobud/blob/main/src-tauri/Cargo.toml)

Возврат: только если audit докажет, что поддержка fork дешевле узкого shell на полном lifecycle, а patched runtime необходим для подтверждённого blocker.

### Полный fork Dictum

Не выбран. Его Tauri/Rust структура, fallback insertion, single-instance и SQLite полезны как reference, но продуктовая модель и cloud-capable зависимости не совпадают с zero-loss aggregate и local-only default WiGigaDict. [Dictum](https://github.com/Vkandil/dictum)

### `dimastatz/whisper-flow` как фундамент

Не выбран. Это Python/FastAPI streaming backend без tray, global hold-to-talk, no-focus overlay, Windows target identity, insertion и durable recovery. Его chunking/benchmark ideas можно использовать в adapter tests.

### Electron

Не выбран. Он упрощает web UI, но добавляет отдельный Chromium/Node runtime и не уменьшает Win32/ASR/recovery работу. Для always-on utility это лишний footprint и поверхность обновления.

### WinUI 3 / C# как основной shell

Не выбран, хотя Microsoft рекомендует WinUI 3 для новых native Windows apps. Он дал бы нативный XAML, но добавил бы .NET/Windows App SDK deployment и оставил бы отдельный Rust/C++/Python ASR boundary; повторное использование AudioBud/Dictum сократилось бы. Unpackaged WinUI также требует установленного или self-contained Windows App SDK runtime. [Windows app platform](https://learn.microsoft.com/en-us/windows/apps/), [deployment](https://learn.microsoft.com/en-us/windows/apps/package-and-deploy/deploy-overview)

Возврат: если Tauri no-focus/IME/accessibility gate провалится и WinUI prototype доказуемо решит blocker меньшей ценой.

### WPF/WinForms

Не выбраны. Они зрелые и хорошо распространяются, но exact ambient overlay и shared settings UI потребуют больше Windows-specific presentation work, не устраняя native insertion и ASR runtime.

### egui/Slint или собственный renderer

Не выбраны. Один Rust-язык не компенсирует цену точного Wispr-like визуального поведения, текстовых настроек, accessibility и frontend tooling.

## Runtime и процессы

### Python как основной desktop runtime

Не выбран. Официальный GigaAM использует Python ≥3.10/PyTorch, но пользовательский clean-install gate прямо запрещает ручной `pip`, поиск DLL и ML environment setup. Python допустим как изолированный development oracle/export tool; bundled Python sidecar — только fallback после провала native GigaAM gate. [GigaAM requirements](https://github.com/salute-developers/GigaAM)

Официальный GigaAM long-form path с `pyannote.audio` и Hugging Face token также не выбран для основного локального MVP. Для записей длиннее 25 секунд принимается только воспроизводимый bundled chunking/VAD path без аккаунта и silent truncation; иначе GigaAM не выигрывает default-engine gate.

### In-process ASR FFI в shell

Не выбран по умолчанию. Native model backend может crash/OOM/зависнуть и унести tray/UI вместе с inference. Отдельный Rust worker немного увеличивает packaging, но сохраняет durable shell и делает restart/health/cancellation проверяемыми.

### FastAPI/WebSocket/localhost server между UI и ASR

Не выбран. Один parent и один child не нуждаются в listening port, HTTP auth, firewall exceptions или server lifecycle. NDJSON over inherited pipes достаточно для finalized-audio MVP.

### Windows Service

Не выбран. Приложение должно жить в интерактивной user session, видеть foreground target, tray и clipboard. Service создаёт session isolation, installer/elevation и IPC-проблемы без пользы MVP.

### Системный или пользовательский FFmpeg для Notetaker

Не выбран. Его наличие, версия, codec set, build flags и лицензия непредсказуемы, а обычный пользователь не должен устанавливать CLI вручную. Найденный локальный `8.1.1-full_build` содержит `--enable-gpl` и подходит только как development oracle. M2 использует [собственный shared LGPL bundle](исследования/2026-08-21-ffmpeg-lgpl-build-spike.md).

### GPL/nonfree FFmpeg full build

Не выбран. Дополнительные encoders/filters не нужны decode-only Notetaker, но меняют license/compliance profile всего bundle. `--enable-gpl`, `--enable-nonfree`, `libx264` и другие неразрешённые external libraries блокируются release audit.

### Только Rust-native decoder (`symphonia`) для Notetaker v1

Не выбран как единственный path: он полезен для части audio formats, но не закрывает нужную video/container matrix. Возврат возможен как оптимизация узкого verified subset после FFmpeg baseline, а не как скрытый fallback с другим output.

### Микросервисы, Docker и Kubernetes

Не выбраны. Нет удалённого backend, нескольких команд или независимого scaling. Они нарушают local-first и компанию из одного человека.

## ASR

### Назначить Whisper или GigaAM победителем без benchmark

Не выбрано. GigaAM силён в русском, Whisper — в multilingual/code-switching, но продуктовый corpus содержит русскую техническую речь с английскими терминами. Выбор делает измерение на пользовательском железе.

### Доверить архитектуру `transcribe-rs`

Не выбрано. Crate полезен как общий spike и MIT-компонент, но ветка 0.3 прямо предупреждает о стабилизации после большой migration, а ONNX path зависит от prerelease `ort`. Доменные DTO, model manifests, retries и errors принадлежат WiGigaDict; dependency заменяется без миграции core.

### Считать найденный Whisper GGUF готовой моделью

Не выбрано. Название кэша не доказывает совместимость. Baseline использует модель формата, явно поддерживаемого pinned runtime, с известным source/license/checksum. Пользовательский GGUF не удаляется и может пройти отдельный probe.

### CUDA-only как default

Не выбран. CUDA/cuDNN compatibility и DLL увеличивают clean-install риск; `transcribe-rs` отдельно отмечает большой размер CUDA ORT. Сначала CPU + Vulkan для Whisper и CPU + DirectML для GigaAM, затем CUDA только при измеримом выигрыше и полностью bundled runtime.

### DirectML как вечная универсальная GPU-абстракция

Не выбран. ONNX Runtime сохраняет поддержку DirectML, но перевёл новую Windows-разработку в WinML. DirectML остаётся bounded benchmark profile для текущего Windows 10/11 MVP, а не неизменным публичным обещанием. [ORT DirectML status](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)

### Облачный ASR/cleanup fallback

Не выбран. Он ломает local-first и может незаметно передать аудио/текст. Будущая cloud-функция требует отдельного явного opt-in и не подменяет локальную ошибку.

### Официальный Python/pyannote long-form GigaAM в production

Не выбран. Он добавляет Python, `pyannote.audio` и Hugging Face token, противоречит Rust-only/offline boundary и создаёт новый model/license lifecycle. Его можно использовать как development oracle; production long-form обязан пройти собственный engine-independent chunk/stitch gate.

### Локальный LLM cleanup в MVP

Не выбран. Это второй model lifecycle, новые искажения смысла, latency и ресурсы. Deterministic cleanup + raw fallback проверяют ценность без генеративного риска.

## Данные и инфраструктура

### PostgreSQL или удалённая БД

Не выбраны. Один Windows user и один application package не нуждаются в database server. SQLite лучше соответствует local-first, backup/export и transaction boundaries.

### JSON-файлы вместо SQLite

Не выбраны как source of truth. Они просты до первого конкурентного update, crash, migration, FK и retention sweep. JSON остаётся export/import/manifest форматом.

### ORM и Tauri SQL из WebView

Не выбраны. Критические constraints и transaction order проще видеть в явном SQL/rusqlite repository. WebView не должен выполнять запросы или обходить permission model core.

### `synchronous=NORMAL` ради скорости

Не выбрано. SQLite допускает потерю последнего WAL commit при power loss в NORMAL. Измеряем цену `FULL`; zero-loss не ослабляется заранее.

### SQLCipher или собственная криптография сразу

Не выбраны без threat model. MVP опирается на текущую Windows user session, per-user ACL и локальность. Если public risk assessment потребует at-rest encryption, ключ оборачивается Windows DPAPI; свой crypto protocol не изобретается.

### Remote telemetry/Sentry по умолчанию

Не выбраны. Diagnostics остаются локальными и content-free; export/send только после preview и действия пользователя.

### Yandex OAuth, private resources и универсальный URL downloader

Не выбраны для Notetaker v1. OAuth/private folders/passwords/no-download обход расширяют secrets, account lifecycle и trust boundary. V1 ограничен одним public downloadable file через отдельную выключенную по умолчанию capability и официальный API.

### Redis/RabbitMQ/Kafka

Не выбраны. Durable jobs уже живут в SQLite, transient coordination — в Tokio. Внешний broker добавляет установку и failure modes.

## Доставка

### MSIX/Store-first

Не выбран для personal alpha. Package identity и Store полезны публичному продукту, но сначала нужен быстрый per-user signed NSIS и доказанный clean install с sidecar/model manager. MSIX возвращается после стабилизации filesystem/update requirements.

### MSI как единственный installer

Не выбран. Он полезен enterprise deployment, но NSIS удобнее для обычного пользователя и portable/current-user вариантов. MSI становится дополнительным артефактом после public/enterprise research.

### Silent self-update до code signing

Не выбран. До защищённой release pipeline пользователь обновляет приложение вручную. После неё updater проверяет обязательную signature; private key имеет backup/rotation plan.

### Модели внутри основного installer

Не выбраны. Installer раздуется на гигабайты и любое обновление приложения станет повторной доставкой весов. Model packages имеют отдельные version/checksum/health lifecycle и могут импортироваться offline.

### Обязательный зарубежный CDN/backend

Не выбран. Personal MVP использует локальные/imported artifacts; public distribution должна иметь manual/offline path и отдельно исследованный российский mirror. Core не знает конкретного CDN.

## Итог

Выбранный стек тратит сложность только на три места, где она защищает главный workflow: durable recovery, Windows insertion/no-focus behavior и сменные local ASR adapters. Всё остальное остаётся локальным, однопроцессным или parent/child, без аккаунтов и серверной инфраструктуры.
