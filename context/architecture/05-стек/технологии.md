# Технологический стек WiGigaDict

## Решение

Personal MVP — Windows-only модульный монолит в одном установочном пакете:

1. `wigigadict.exe` — Tauri 2 shell на Rust: lifecycle, durable state, capture, cleanup, insertion, recovery и UI bridge.
2. `wigigadict-asr.exe` — управляемый Rust sidecar: загрузка модели и локальный inference за узким versioned IPC-контрактом.
3. React/TypeScript WebView — только представление и пользовательские команды; он не получает прямой доступ к БД, произвольной файловой системе, shell или Windows injection API.

ASR-победитель не назначается архитектурным решением. Whisper и GigaAM проходят одинаковый локальный benchmark, после чего один профиль становится default MVP, а общий adapter contract остаётся независимым от модели.

Состояние источников и локальной среды проверено **21 августа 2026 года**. Точные версии зависимостей фиксируются lock-файлами и `rust-toolchain.toml`; автоматические major/minor upgrades запрещены без regression gate.

## ASR gate: что именно сравниваем

Одинаковый corpus и одинаковый PCM artifact прогоняются минимум через:

1. Whisper large-v3-turbo в подтверждённом whisper.cpp-compatible формате: CPU и Vulkan.
2. GigaAM-v3 CTC/e2e-CTC варианты, которые проходят export/compatibility test: ORT CPU и DirectML.
3. Один warm и один cold profile каждого варианта; повтор после worker crash; offline run; clean-install run.

В корпус обязательно входят записи длительностью 5, 15, 25, 30 и 60 секунд. Официальный `GigaAM.transcribe` заявлен только для аудио до 25 секунд, а `transcribe_longform` добавляет `pyannote.audio` и Hugging Face token. Поэтому default GigaAM profile обязан доказать локальный deterministic chunking/VAD path без silent truncation и пользовательского token. Если он этого не делает, GigaAM не проходит MVP gate независимо от WER на коротких фразах.

30/60-second success — необходимое, но недостаточное условие для Notetaker. M2 дополнительно требует soak до 4 часов с immutable raw/stitch timings, zero lost/duplicate seam markers, финальным marker drift ≤1 секунды, bounded resources, crash/resume и повторным Dictation preemption. Window/overlap/VAD выбираются этим benchmark и фиксируются profile/config hash, а не задаются архитектурой заранее. Полный протокол: [long-form spike](исследования/2026-08-21-long-form-asr-spike.md).

Порядок выбора уже установлен: **надёжность → точность → задержка → ресурсы**. Измеряются WER/CER, technical-token error rate, p50/p95 release-to-result, RTF, peak RAM/VRAM, model-load time, crash/restart и число unrecoverable outcomes.

`transcribe-rs` принимается в production path только если:

- exact pin собирается без git patches и без пользовательского Python;
- GigaAM output совпадает с эталоном официального Python runtime на regression corpus в согласованном допуске;
- Whisper output проходит regression против pinned whisper.cpp CLI/library;
- CPU/GPU selection, cancellation и repeated model load не дают leak/crash;
- offline и clean-install gates воспроизводимы;
- dependency/license/SBOM audit не обнаруживает неприемлемую цепочку.

Если gate не пройден, доменная архитектура не меняется: adapter заменяется прямым `whisper.cpp` binding и/или собственным тонким ORT GigaAM adapter. Bundled Python sidecar допустим только как временный benchmark oracle, не как silent production dependency.

## Совместимость найденных локальных моделей

- Кэш `unslothai/whisper-large-v3-turbo-GGUF` сохраняется, но не объявляется runtime-ready. Официальные whisper.cpp model downloads перечисляют GGML `.bin`; совместимость конкретного GGUF должна быть доказана probe, а не угадана. Для baseline берётся checksum-pinned официальный `ggml-large-v3-turbo*.bin`. [whisper.cpp models](https://github.com/ggml-org/whisper.cpp/blob/master/models/README.md)
- Кэш `ai-sage/GigaAM-v3` содержит PyTorch weights. Native production chain требует воспроизводимого ONNX package с manifest, vocab/config и output parity; наличие `pytorch_model.bin` само по себе не означает готовность ORT adapter.
- Ничего из существующих кэшей автоматически не перемещается и не удаляется. Model manager либо импортирует проверенный artifact, либо создаёт отдельный managed package.

## Экспериментальные жетоны

1. **Локальный AI/ASR** — неизбежный первый жетон продукта.
2. **`transcribe-rs` как общий native adapter spike** — второй жетон; оправдан возможностью одним Rust boundary проверить Whisper и GigaAM без Python в production.
3. **Резерв** — не расходуется сейчас. Он понадобится только если stable Tauri/Win32 не обеспечивает no-focus overlay или insertion matrix и потребуется ограниченный native component.

Tauri, React, SQLite, Tokio, NSIS и прямые Win32 APIs экспериментальными жетонами не считаются: это зрелые и узко используемые инфраструктурные решения.

## Российский публичный продукт

На personal MVP нет сервера, аккаунта, удалённой telemetry или платежей, поэтому data residency/provider stack отсутствует. Перед добавлением cloud sync, аккаунтов или billing требуется отдельный legal/architecture gate с повторной проверкой на дату запуска.

На дату проверки официальный текст части 5 статьи 18 152-ФЗ запрещает при интернет-сборе первичную запись/хранение данных граждан РФ в зарубежных базах, кроме перечисленных законом случаев. Это аргумент не добавлять зарубежный control plane «на будущее», но не юридическое заключение. [Официальный текст 152-ФЗ](https://ips.pravo.gov.ru/api/ips/legislation/document?baseid=None&hash=98490812b3409e2a8d78a11ca9010f434ea3d9250a11dbbdb78690cd5551bdd6)

При начале продаж отдельно проверяются применимость 54-ФЗ/ККТ, налоговый режим, чеки и актуальные российские провайдеры; эти требования меняются и не входят в desktop core. [54-ФЗ на сайте ФНС](https://www.nalog.gov.ru/rn77/about_fts/docs/3909988/)
