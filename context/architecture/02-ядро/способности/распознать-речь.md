# Способность: распознать речь локально

## Когда применять

- Finalized audio и session marker уже durability-committed по two-storage protocol, а пользователь завершил диктовку.
- Пользователь явно повторяет ASR для recoverable session с доступным audio artifact.
- M2 Notetaker worker получает canonical durable PCM chunk и engine-independent artifact contract; job и checkpoint уже committed.

## Когда НЕ применять

- До durable commit аудио, для бесконечной фоновой транскрибации или до long-form gates.
- Через cloud fallback, если локальный runtime не готов.
- Через Dictation FSM для импортированной записи: Notetaker имеет отдельный aggregate и только переиспользует adapter/runtime.

## Примеры

- **Good:** adapter получает immutable audio reference, profile/version и создаёт одну raw transcript version.
- **Bad:** после CUDA-ошибки приложение незаметно отправляет аудио внешнему API ради «бесшовности».

## Что может пойти не так

Runtime отсутствует, health check устарел, timeout превышен, процесс падает или возвращает дубликат. Применять single-flight по session/audio/adapter version, watchdog `T_STT`, максимум один классифицированный transient retry; при отказе сохранить audio и открыть recovery.

Для Notetaker canonical sidecar output — монотонные сегменты `{start_ms, end_ms, text}` в целых миллисекундах от начала media. Raw timings immutable; stitching создаёт отдельную version. Window/overlap/VAD выбираются benchmark, а не API-контрактом. Одновременно resident только один runtime: Dictation вытесняет Notetaker на chunk boundary.

## Статус реализации M1 / Step 10

- Protocol `0.2.0` задаёт bounded NDJSON commands/events, строгий Whisper engine/profile, heartbeat/cancel и монотонные segments в пределах WAV.
- SQLite dispatcher выдаёт один generation-bound CAS lease, после expiry возвращает тот же `AsrAttempt` и допускает не более одного transient retry; raw transcript коммитится immutable и idempotent по source attempt.
- Desktop supervision работает в отдельном thread, поэтому shell/capture не ждут ASR. Signed Step 9 manifest связывает model path и SHA-256, а ASR worker поставляется вместе с приложением, как sidecar, и не входит в model package ([ADR-012](../../06-решения/журнал-решений/2026-08-31-012-worker-в-приложении.md)); adapter вызывает фактический frozen `run-whisper` CLI из Step 4 и удаляет transient raw NDJSON из temp после bounded parse.
- Адаптер принимает любой ggml Whisper package из подписанного каталога ([ADR-011](../../06-решения/журнал-решений/2026-08-31-011-подписанный-каталог-моделей.md)), а не одно замороженное имя модели: пакет привязан к lease по `profile_id` и точному совпадению runtime settings. Пакет ADR-006 сохраняет собственный вариант `EngineKind`, чтобы baseline Step 16 остался байт-идентичным; остальные едут как `whisper_ggml`. Другой `engine_family` по-прежнему отклоняется — ему нужен другой worker.
- Golden-flow с реальной моделью остаётся Step 16, clean-install runtime packaging — Step 17; эти поздние gates не меняют durable контракт Step 10.
