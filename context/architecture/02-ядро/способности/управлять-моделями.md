# Способность: управлять локальными моделями

## Когда применять

- Пользователь явно устанавливает, выбирает, проверяет, прогревает или удаляет model package/runtime profile.
- Система выполняет health check или разрешённый warm-up выбранного локального profile.

## Когда НЕ применять

- Для скрытой загрузки больших весов, cloud fallback или автоматической замены рабочей модели.
- Для удаления package, который нужен active/recoverable session.

## Примеры

- **Good:** показать source/license/size, скачать resumable, проверить checksum, атомарно установить и только затем переключить active profile.
- **Bad:** удалить старую модель до health check новой, оставив приложение без рабочего runtime.

## Что может пойти не так

Сеть обрывается, checksum не совпадает, диск заполнен, runtime present but not ready. Partial download остаётся resumable, active package не меняется до commit, self-test возвращает конкретный код; наличие весов и readiness хранятся раздельно.

Каталог доступных моделей поставляется как подписанные данные (`catalog.json` + открепленный `catalog.sig`), а не как список в UI: [ADR-011](../../06-решения/журнал-решений/2026-08-31-011-подписанный-каталог-моделей.md). Запись каталога несёт точные байты подписанного manifest пакета, поэтому размер, лицензия и версия читаются из манифеста и не расходятся с тем, что будет установлено. Каталог обещает проверяемость, а не качество: точность и скорость показываются только для моделей, измеренных этим проектом. По той же причине запись не сужает язык там, где модель его не сужает: все whisper-модели каталога многоязычные и несут `languages: ["multi"]`, а отбора по языку в UI нет — он вернётся вместе с первой моделью на ограниченный набор языков.
