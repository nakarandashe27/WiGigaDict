# Способность: собрать диагностику

## Когда применять

- Пользователь разбирает ошибку и создаёт local diagnostic bundle с preview.
- Система пишет структурированное техническое событие о стадии, latency, runtime, insertion method или error code.

## Когда НЕ применять

- Для скрытой telemetry, постоянной записи аудио/текста или автоматической отправки bundle наружу.
- Для подмены recovery: лог не является единственной копией пользовательского результата.

## Примеры

- **Good:** bundle показывает версии, timings и коды, удаляет пути/текст, затем просит пользователя сохранить или отдельно отправить файл.
- **Bad:** при crash автоматически загрузить audio и transcript создателю приложения.

## Что может пойти не так

PII попадает в filename/path, redaction неполна, bundle частично собран или слишком велик. Использовать allowlist полей, preview, size limit и manifest missing sources; отправка наружу всегда отдельна от создания.

## Статус реализации M1 / Step 15

- ✅ Rust shell пишет versioned NDJSON только через закрытые enums и bounded allowlist metadata. Essential события работают всегда; расширенные progress-события включаются отдельной настройкой.
- ✅ Активный trace синхронизируется на запись, восстанавливает только незавершённый crash-tail и fail-closed отклоняет повреждённую полную строку, неизвестную схему/entry или reparse point. Rolling defaults: 30 дней, 100 MiB, 25 файлов и 4 MiB на файл.
- ✅ Bundle детерминированно собирается из валидированных локальных trace-файлов, ограничен 100 MiB, содержит manifest/source hashes/event counts и никогда не включает audio, transcript, clipboard, window title, absolute path, environment или secret.
- ✅ UI сначала показывает content-free preview с count/size/schema/SHA-256 id и списком исключений. Экспорт требует абсолютный новый `.wigigadiag.json` path и точное подтверждение; файл создаётся через `.part → final`, не отправляется наружу и не возвращает полный path в receipt.
- ✅ Targeted tests восстанавливают порядок recovery/focus/commit failure без content, проверяют crash-tail, retention/restart, malformed/future input, marker secrets, confirmation и no-overwrite.
