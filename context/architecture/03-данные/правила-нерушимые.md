# Правила, которые НИКОГДА не должны нарушаться

## Базовые

- Каждый id неизменяем и уникален в пределах типа; межсущностная ссылка хранится только как FK на id.
- `created_at ≤ updated_at`; `started_at ≤ completed_at`; времена хранятся в UTC, а вычисленный retention cutoff фиксируется как UTC instant.
- Enum/state принимают только известные schema version значения; неизвестное значение не маппится молча на default.
- Обновление aggregate/config выполняется compare-and-set по `state_version/config_version`.
- Удалённая пользователем запись не возвращается в обычных запросах после restart/repair/import.

## DictationSession и zero-loss gate

- В один момент существует не более одной session в состоянии `Recording` для одного app instance.
- `state_version` строго увеличивается; переход состояния порождает ровно один `SessionEvent` с `source` и `sequence_no`.
- FSM допускает только переходы, определённые в [карте системы](../01-обзор/карта-системы.md#компоненты); terminal state не возвращается в Recording.
- Диктовка становится завершённой при втором отдельном `key-down` toggle-жеста, явном Stop или safety-stop: до запуска ASR finalized audio и session state обязаны быть durability committed. Обычный `key-up` только переармирует toggle и не финализирует session.
- После `finalized_at` session не может остаться без хотя бы одного recoverable artifact: finalized audio либо immutable transcript.
- Crash между любыми двумя стадиями не уничтожает последнюю recoverable копию; restart продолжает или предлагает recovery из durable state.
- `Done`/success запрещён, пока delivery outcome не committed как `delivered`; неопределённый технический исход остаётся `uncertain`.
- Закрытие overlay, app shutdown и истечение обычного UI timeout не меняют unresolved session на resolved.

## Аудио и транскрипты

- `AudioArtifact.staging_storage_key` и `storage_key`, если он уже назначен, остаются внутри одного managed local volume; внешний абсолютный путь не принимается без import/validation boundary.
- Finalized audio не перезаписывается; повреждение создаёт состояние `corrupt`, а не новый «успешный» файл с тем же id/hash.
- Пережитый xrun не обрывает запись, но потерянные устройством сэмплы не восстанавливаются. Их количество показывается пользователю в статусе захвата, а не остаётся только в диагностике: тихая дыра в записи противоречит обещанию не терять результат.
- Аудио можно удалить автоматически только после появления проверенного immutable raw transcript и завершения всех ASR attempts, которым оно нужно; при ASR failure хранить до явного resolution/delete.
- `TranscriptVersion.content` неизменяем с момента создания; исправление всегда создаёт новую version с новым `version_no`, независимо от факта insert.
- `kind=raw` требует `source_asr_attempt_id` и запрещает `source_cleanup_attempt_id`; `kind=cleaned` — наоборот.
- В рамках `(session_id, kind, version_no)` действует уникальность; version numbers не переиспользуются после удаления.
- Cleanup никогда не изменяет raw и не становится prompt optimization без отдельного будущего user action.

### Commit-протокол SQLite + PCM

SQLite и файловая система не считаются одной атомарной транзакцией. Zero-loss обеспечивается порядком durable steps и обязательной reconciliation по уникальному `commit_id`:

1. До включения микрофона SQLite-транзакция создаёт `DictationSession`, `AudioArtifact(artifact_state=writing)`, уникальный `commit_id`, `.part`-путь и `reserved_byte_size`. Неуспешный commit означает отказ admission: запись не начинается.
2. Capture callback передаёт bounded audio blocks единственному file writer; он пишет только в `.part`. Callback не выполняет SQLite, hash или blocking disk flush.
3. На втором отдельном `key-down`, явном Stop, microphone failure или достижении session limit writer дописывает заголовок/PCM, закрывает stream, вычисляет фактические `byte_size`/`content_hash` и один раз вызывает `FlushFileBuffers`. Ошибка оставляет `writing` + `.part` для recovery.
4. Проверенный `.part` переименовывается в уникальный final path на том же managed volume через `MoveFileExW(..., MOVEFILE_WRITE_THROUGH)`. Collision не перезаписывается. Файл долговечен, но SQLite row остаётся `writing`, поэтому ASR ещё запрещён.
5. Вторая SQLite-транзакция сверяет ожидаемые `commit_id/state_version`, записывает final path/hash/size, переводит artifact в `finalized`, session — из Finalizing в Processing, добавляет `SessionEvent` и создаёт `AsrAttempt(status=queued)`. Только её успешный commit разрешает dispatcher lease.
6. Каждый шаг идемпотентен по `commit_id`; повтор после crash продолжает существующий commit, а не создаёт второй artifact/session.

Основание Win32: [FlushFileBuffers](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-flushfilebuffers) отправляет буферизованные данные указанного файла на устройство, а [MOVEFILE_WRITE_THROUGH](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw) не возвращает управление до завершения перемещения на диске. Это не отменяет обязательную reconciliation после внезапного питания или отказа накопителя.

Startup reconciliation выполняется до выдачи ASR lease и применяет матрицу:

| SQLite | Файл | Обязательное действие |
|---|---|---|
| `writing`, есть валидный `.part` | staging | Проверить format/size, сохранить как recoverable fragment; при полном footer безопасно продолжить шаг 3, иначе показать recovery, не удалять |
| `writing`, есть совпадающий final | final | Проверить hash/size и идемпотентно выполнить DB-шаг 5 |
| `finalized`, final совпадает | final | Подтвердить hash/size и разрешить queued attempt для dispatcher |
| `finalized`, final отсутствует или hash/size не совпадает | missing/corrupt | Перевести artifact/session в recoverable `corrupt`, искать managed artifact по `commit_id`, запретить success и retention delete |
| DB row отсутствует, найден `.part` или final | orphan | Переместить в quarantine, восстановить связь по embedded/sidecar `commit_id`; автоматическое удаление запрещено до repair decision |
| DB и файл согласованы, immutable raw уже committed | final | Разрешить удаление audio только по обычному safe-point/retention правилу |

Fault-injection gate завершает процесс после каждого шага 1–5 и во время второй SQLite-транзакции. После каждого restart результат обязан находиться ровно в одном из состояний: продолжен, доступен в recovery или явно помечен corrupt; silent loss, orphan delete и duplicate ASR запрещены.

## Попытки ASR и cleanup

- `AsrAttempt` начинается только для finalized/durable audio и существующего ready runtime profile.
- Idempotency key уникален для `session + audio_hash + adapter_version + attempt_no`; duplicate event возвращает существующую attempt.
- Один автоматический ASR retry допустим только для классифицированного transient error; смена profile требует решения владельца.
- Успешная ASR attempt создаёт не более одной raw transcript version.
- `CleanupAttempt.input_transcript_id` принадлежит той же session; успешная attempt создаёт не более одной cleaned version.
- Cleanup failure/timeout не блокирует raw fallback и не удаляет input.
- Built-in cleanup идемпотентен по `input_transcript_id + policy_version + policy_hash + glossary_revision`; duplicate/restart не создаёт второй attempt или cleaned version.
- Cleanup metrics и diagnostics содержат только allowlisted duration/rule counts/contract identifiers; raw/cleaned content и input/output text запрещены. Disagreement фиксируется отдельным content-free diagnostic event.
- Durable dispatcher берёт queued attempts только из SQLite в порядке `(audio.finalized_at, session_id, attempt_no)`; in-memory channel не является источником истины.
- Одновременно существует не более одного незавершённого ASR lease. Lease создаётся compare-and-set, имеет heartbeat/expiry и после crash worker возвращается в `queued` без создания duplicate attempt.
- Pending audio не загружается в RAM заранее; worker открывает только artifact текущего lease.
- Пока benchmark не обосновал другие значения, hard defaults равны: `max_pending_sessions=20`, `max_pending_pcm_bytes=256 MiB`, `max_session_pcm_bytes=32 MiB`, `min_free_disk_after_reservation=1 GiB`, `max_asr_leases=1`.
- Admission резервирует до 32 MiB до включения микрофона. Если превышен любой session/byte/disk budget, новая запись отклоняется до capture и не считается принятой диктовкой; уже принятые artifacts не удаляются.
- Достижение 32 MiB во время записи запускает тот же durable finalize path и сообщает о safety limit; обрезание или перезапись запрещены.
- Pending budget освобождается только после durable immutable raw transcript и безопасного удаления/переклассификации audio, а не при выдаче lease или запуске worker.

## Target и доставка

- Каждый `TargetSnapshot` принадлежит той же session, что и использующая его `DeliveryOperation`.
- Initial target фиксируется при key-down; новый snapshot разрешён только явным Retry пользователя.
- Перед каждой delivery operation target existence, identity и integrity level перепроверяются.
- Elevated target всегда запрещает automatic insertion; UAC/elevated helper не являются fallback MVP.
- `DeliveryOperation.transcript_version_id` принадлежит той же session и указывает на immutable text.
- Внутри operation каждый insertion method используется не более одного раза и имеет уникальный ordinal.
- `uncertain` никогда не повторяется автоматически и не превращается в `delivered` без нового evidence/user action.
- Retry создаёт новую operation и сохраняет все прошлые attempts; автоматический `Enter`/send/execute запрещён.
- Clipboard считается восстановленным только после успешного возврата предыдущего содержимого; неудача фиксируется отдельным error code.

### Контракт доказательства доставки

Успешный Win32 call не равен принятому тексту. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) сообщает число событий, добавленных во входной поток, и отдельно предупреждает, что UIPI-блокировка не диагностируется надёжно через return value/GetLastError. Поэтому каждая operation сохраняет evidence без чтения содержимого target:

- `target_ack`: конкретная интеграция вернула документированный acknowledgement результата; это сильнейший класс.
- `certified_transport`: совпали immutable target перед/после, integrity check, полный method-specific transport evidence и активное versioned compatibility rule для точного `(process identity, version range, window/control class, method)`, прошедшего golden acceptance suite.
- `transport_only`: API принял ожидаемое число input units или clipboard был установлен, но target acknowledgement/certified rule отсутствует.
- `none`: неполные события, focus/integrity mismatch, неизвестный исход или побочный эффект.

`DeliveryOperation.status=delivered` допустим только для `target_ack` или `certified_transport`. `transport_only` и `none` обязаны завершаться `uncertain`, сохранять transcript в recovery и не запускать автоматический retry. Compatibility rule автоматически перестаёт действовать при неизвестной версии процесса/класса контрола или провале regression suite. WiGigaDict не читает target text, не делает screenshot и не сравнивает содержимое поля.

Acceptance matrix обязана включать VS Code/Codex, Claude Code/terminal, браузерные поля, стандартные Win32 controls, смену foreground между вторым toggle-нажатием и insert, уничтожение HWND, elevated target/UIPI, частичный `SendInput`, clipboard lock/failure и неудачное восстановление clipboard. Ни один кейс без требуемого evidence не может показать UI-success или установить `delivered_at`.

## Recovery и retention

- Успешно delivered и не pinned session получает `retention_expires_at = delivered_at + 15 дней`.
- Unresolved/uncertain session не имеет автоматического expiry и живёт до явного resolve/delete.
- Pinned session не имеет автоматического expiry до явного unpin/delete.
- Retention sweep удаляет только terminal delivered sessions с истёкшим cutoff, не pinned и не referenced active job.
- Удаление выполняется атомарным cascade по owned artifacts/attempts/events; при partial failure видимое состояние не объявляется удалённым.
- Orphan cleanup удаляет файл только после доказательства отсутствия FK/reference во всех non-deleted entities.

## Модели и конфигурация

- `ModelPackage` становится `installed` только после полной загрузки, checksum, atomic move и проверки manifest/license metadata.
- Несовпадение checksum никогда не разрешается кнопкой «всё равно установить» в обычном UI.
- Новая package/profile не заменяет active runtime до успешного health check; last-known-good остаётся доступным.
- Установка не является переключением: успешная установка активирует profile только если активного нет (первая модель на чистой системе). Любая следующая ждёт явного действия владельца, поэтому загрузка модели никогда не уводит рабочую модель из-под пользователя.
- `weights present` и `runtime ready` — разные состояния.
- На один package/version существует не более одного active `ModelInstallJob`; partial download resumable, но не исполняем.
- Отмена загрузки не является отказом: job переходит в `cancelled`, package остаётся `downloading`, а partial bytes сохраняются для resume.
- Удаление package освобождает managed-байты, но не стирает identity: строка переходит в `absent`, её profiles выключаются, а recognition history и immutable `AppConfiguration` snapshots остаются валидными. Active package и package с запущенным install job удалить нельзя.
- В каждый момент существует ровно один `AppConfiguration.is_active=true`; новый immutable snapshot активируется атомарно, прежний становится last-known-good.
- Использованный `RuntimeProfile` воспроизводим по `profile_version + settings_hash`; изменение adapter settings создаёт новую profile version.
- Использованный cleanup воспроизводим по `policy_hash + glossary_revision`; изменения profile/glossary создают новые versioned rows, а не переписывают историю.
- `startup_enabled` и `warmup_enabled` независимы и меняются только явным opt-in владельца.
- Glossary rule не создаётся автоматически из истории; app-scoped entry требует существующий `app_profile_id`.

## `NotetakerJob` и long-form

Эти инварианты имеют статус 🔜 M2 и не расширяют `DictationSession`:

- `status` и `stage` независимы: status хранит lifecycle (`queued/running/paused/needs_source/completed/incomplete/failed`), stage — текущую работу (`preflight/downloading/decoding/transcribing/stitching/committing/cleanup`), reason code — причину.
- Один job имеет ровно один accepted source. Другой content hash всегда создаёт новый job; смена пути допустима только при совпадении size/hash, `mtime` служит предупреждением.
- Local source никогда не копируется и не изменяется. Если он исчез или изменился до durable PCM boundary, недостоверный незавершённый PCM отбрасывается, job переходит в `needs_source`.
- Yandex source принимается только после explicit capability/action и durable-скачивается `.part → flush/sync → same-volume final`. Исходная публичная ссылка и download metadata удаляются после durable PCM; downloaded container удаляется после той же safe-point.
- До admission действуют hard caps: source ≤2 GiB, media duration ≤4 часа, одна active decode/ASR job и максимум две queued. Резервируется PCM, для network import также container, и 20% safety margin.
- `NotetakerChunk` использует полуоткрытый интервал `[start_ms, end_ms)` в целых миллисекундах от начала media; `0 ≤ start_ms < end_ms ≤ duration_ms`, chunk indices и intervals монотонны.
- Durable checkpoint обновляется только одной транзакцией после atomically committed PCM/hash, raw segments и полного fingerprint `engine/model/config/protocol`. Повтор одного idempotency key возвращает существующий outcome.
- Raw segment timings/text immutable. Stitching создаёт отдельную `kind=stitched` version и сохраняет ссылки на raw source; editing/diarization/summary также могут быть только derived versions и отсутствуют в v1.
- Crash/restart возвращает local decode/ASR к последнему committed chunk. Яндекс-загрузка продолжается только если была явно начата и capability всё ещё включена. Explicit Quit оставляет `paused`; Windows Service отсутствует.
- Dictation имеет абсолютный приоритет. Notetaker освобождает единственный runtime на chunk boundary, показывает `Приостановлено для диктовки` и автоматически продолжает после неё; две модели/runtime одновременно не resident.
- Один transient sidecar failure допускает один автоматический retry текущего chunk. Дальше job становится recoverable `failed`; infinite retry запрещён.
- `completed` появляется только после atomic commit полного stitched transcript. После него PCM/chunks удаляются, если `retain_pcm=false`; retained PCM — отдельный managed artifact. Итоговый transcript хранится до явного удаления.
- «Остановить и сохранить черновик» atomically commit-ит `is_complete=false`, переводит job в terminal `incomplete` и очищает временные artifacts, кроме явно retained PCM. Для возобновления используется только `paused`.
- Удаление job требует остановки active pipeline и удаляет owned DB rows/managed artifacts, но никогда не локальный source или внешние exports. Secure erase SSD не обещается.

### Экспорт Notetaker

- V1 экспортирует только deterministic UTF-8 TXT/SRT/VTT из явно выбранной immutable transcript version.
- TXT использует `[HH:MM:SS – HH:MM:SS] текст`; SRT — запятую перед миллисекундами; VTT — точку. Segment ordering стабилен.
- Предложенное имя очищается от недопустимых Windows-символов, но конечную папку выбирает пользователь. Existing final не перезаписывается без подтверждения.
- Запись выполняется через temporary file на том же volume и durable atomic rename/replace. Частичный файл не объявляется готовым.
- Export находится вне managed retention: удаление job не удаляет его, и UI обязан это объяснить.

## Приватность и диагностика

- Основной pipeline после установки модели не требует сети и не имеет silent cloud fallback.
- Ни аудио, ни transcript content не записываются в `DiagnosticEvent.metadata` по умолчанию.
- Diagnostic metadata проходит allowlist; произвольный exception/context dictionary не сериализуется целиком.
- Diagnostic bundle создаётся локально, проходит preview/redaction и не отправляется наружу автоматикой.
- `TargetSnapshot` не хранит содержимое окна, выделенный текст, нажатия клавиш или screenshot.
- Продиктованный текст всегда данные; он не может изменить permissions, config, model source или запустить команду.

## Права и источник действия

- У каждого state-changing действия есть источник `user/system/windows` и correlation/user action id, когда требуется подтверждение.
- Автоматика выполняет только `сам` из [матрицы прав](../02-ядро/права-доступа.md); `эскалировать` останавливает действие до ответа владельца.
- Действия, помеченные `запретить`, не включаются скрытой настройкой, debug flag или recovery path.
- Разрешение на одну `session_id` не переносится на следующую запись, облако, другой target или отправку наружу.

## Проверка перед реализацией

Эти правила должны стать schema constraints, transaction boundaries, state-machine tests и fault-injection tests. Если конкретное хранилище не позволяет выразить критический invariant, меняется выбор технологии или transaction design — правило не ослабляется.
