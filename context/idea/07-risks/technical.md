# Технические риски

## R-02 — Вставка ломается в целевых приложениях

**Уровень:** critical · **BLOCKER**

**Что пошло не так.** В части IDE, терминалов, браузерных полей и elevated-приложений текст не вставлялся, вставлялся не туда или терялся без понятного сообщения.

**Почему.** Windows focus, privilege boundaries, Text Services Framework и поддерживаемые механизмы ввода различаются между приложениями. Одного clipboard или `SendInput` недостаточно, а технический факт вызова API не доказывает, что текст оказался в нужном поле.

**Что сделать сейчас.** Реализовать capture исходного target, лестницу native Unicode → `SendInput` → clipboard, восстановление clipboard и обязательный recovery при неопределённости. До основного UI провести [Win32 proof-of-concept](../05-research/methodologies.md#6-вставка-и-восстановление) и тестовую матрицу приложений.

**Ранний сигнал:** insertion success rate по каждому приложению; отдельно — silent/uncertain delivery count.

**Статус M1 / Step 12.** Production engine фиксирует target при key-down, повторно проверяет HWND/process/thread/classes/integrity/Windows build до и после transport, сохраняет immutable attempt evidence и не повторяет неоднозначный ввод. Полный `SendInput` без acknowledgement или активного certified rule остаётся `transport_only → uncertain`; registry v1 пока пуст. Windows 11/unknown build и elevated target блокируются до input. Остаточный product blocker — сертификация реальных compatible paths и golden flow Step 16, а не риск ложного `delivered`.

## R-04 — Code-switching портит технический смысл

**Уровень:** high

**Что пошло не так.** Смешанная RU/EN речь превращала имена API, команды, пути, аббревиатуры и бренды в правдоподобный, но неверный текст.

**Почему.** Язык и словарь меняются внутри одной фразы, а обычная word error rate скрывает особую стоимость ошибки в техническом токене. Cleanup способен дополнительно «нормализовать» ошибку и сделать её менее заметной.

**Что сделать сейчас.** Собрать реальный корпус 30–60-секундных технических диктовок, выделить technical-token error rate и сравнить Whisper/GigaAM на нём. Добавить deterministic glossary, raw/cleaned сравнение и только после benchmark решать, нужен ли отдельный technical profile.

**Ранний сигнал:** technical-token error rate по именам, API, командам, путям и английским терминам.

Основание: [RU/EN-дельта](../05-research/delta.md#2-ruen-персонализация-для-технической-речи), [метрики MVP](../04-mvp/success-metrics.md).

## R-05 — Задержка после release разрушает workflow

**Уровень:** high

**Что пошло не так.** После отпускания hotkey пользователь ждал настолько долго и непредсказуемо, что повторял фразу, переключался на клавиатуру или создавал две параллельные сессии.

**Почему.** Cold start, локальная инференция, cleanup и вставка складываются в одну субъективную паузу. Средняя latency скрывает редкие длинные хвосты, а fallback с GPU на CPU может резко изменить поведение без понятного объяснения.

**Что сделать сейчас.** Измерять стадии отдельно, прогревать выбранную модель, показывать текущую стадию и строить решение по cold/warm p50/p95 на целевой машине. Численный порог установить после локального benchmark, как уже зафиксировано в [success metrics](../04-mvp/success-metrics.md).

**Ранний сигнал:** p95 release-to-insert latency и доля повторно начатых диктовок во время обработки.

## R-06 — Cleanup незаметно меняет намерение

**Уровень:** high

**Что пошло не так.** Meaning-preserving cleanup удалял отрицания, оговорки, ограничения или важные qualifiers в техническом задании.

**Почему.** Пользователь видит уже гладкий результат и может не заметить небольшое смысловое смещение. Одинаковая политика очистки для сообщения, кода и промпта создаёт разные классы ошибок.

**Что сделать сейчас.** Всегда хранить raw рядом с cleaned, начать с консервативных deterministic правил и собрать regression corpus с отрицаниями, самоисправлениями и ограничениями. Генеративную prompt optimization оставить отдельной явной командой.

**Ранний сигнал:** cleanup disagreement rate — доля случаев, где пользователь возвращается к raw или отменяет изменение.

Основание: [принцип сохранения намерения](../06-principles/README.md#3-продукт-улучшает-форму-но-не-присваивает-намерение).
