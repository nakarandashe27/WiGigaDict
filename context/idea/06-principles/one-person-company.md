# Компания из одного человека

## Что это означает сейчас

На personal-first этапе продукт проектируется, собирается, тестируется и поддерживается одним человеком с помощью AI-инструментов. Это не обещание навсегда оставаться без команды, а ограничение на операционную сложность: каждый компонент должен быть понятен, воспроизводим и обслуживаем без отдельной команды инфраструктуры или ML-инженеров.

## Правила scope

- Один доказанный Windows workflow раньше нескольких платформ и сценариев.
- Один выбранный по benchmark ASR runtime блокирует MVP; второй адаптер — ближайшее расширение.
- Нет обязательного backend, аккаунтов, billing и cloud control plane в personal MVP.
- Meeting assistant, voice OS, TTS, agent actions, macOS и enterprise management отложены.
- Новая функция принимается только вместе с ценой поддержки, диагностики, миграций и тестирования.

## Build vs reuse

Не изобретать зрелый компонент, если его можно безопасно переиспользовать. Но форк не считается бесплатным: он принимается только после проверки лицензии, происхождения кода, сетевых вызовов, updater, installer, runtime boundary, Windows insertion и воспроизводимости сборки.

Предпочтительный порядок:

1. переиспользовать небольшой проверенный компонент;
2. адаптировать ограниченный модуль из подходящего open-source проекта;
3. форкнуть продукт только при доказанной экономии полного lifecycle cost;
4. написать своё для защищаемой дельты: recovery, app compatibility, RU/EN personalization и прозрачного cleanup.

## Архитектура для маленькой команды

- модульный монолит вместо распределённой системы;
- чёткие границы `capture / ASR / cleanup / insertion / recovery / UI`;
- локальная схема данных с простыми миграциями;
- минимум языков и runtime-процессов, совместимый с выбранными моделями;
- воспроизводимая сборка и подписываемый installer;
- автоматические smoke-тесты golden flow и матрицы вставки;
- диагностический пакет, позволяющий разбирать проблему без удалённого доступа к ПК.

## Где автоматизация обязательна

- сборка и упаковка Windows installer;
- checksum и публикация моделей/артефактов;
- benchmark Whisper/GigaAM на фиксированном корпусе;
- тест 100 завершённых диктовок без потери результата;
- regression matrix для VS Code, Codex, терминалов, браузера и стандартных Windows controls;
- проверка лицензий и зависимостей перед релизом;
- выпуск changelog и rollback-пакета.

## Рост без переписывания ядра

Будущая коммерциализация не должна заставить заменить personal-first core. Для этого заранее нужны adapter boundary моделей, policy boundary Local/Cloud, версионируемые настройки/данные и отделённый Windows shell. Аккаунты, командные политики, централизованное развёртывание и macOS подключаются вокруг доказанного pipeline, а не внутри него.

## Критерий отказа от функции

Если функция требует постоянного облачного сервиса, ручной поддержки каждого пользователя, второго параллельного UI, отдельной ML-платформы или резко увеличивает поверхность безопасности, она не входит в MVP без доказательства, что решает главный [Job to be Done](../03-audience/jobs-to-be-done.md).
