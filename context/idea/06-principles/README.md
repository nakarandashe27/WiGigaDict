# Принципы продукта

Эти принципы превращают продуктовые приоритеты в правила принятия решений. Они выведены из [болей первичной аудитории](../03-audience/jobs-to-be-done.md), [архитектурных паттернов рынка](../05-research/methodologies.md) и [защищаемой дельты проекта](../05-research/delta.md).

## 1. Локальность — проверяемое поведение, а не обещание

Основной пользовательский цикл должен работать без аккаунта, подписки и передачи аудио или текста внешнему сервису. Любая будущая облачная функция существует только как явный opt-in с указанием провайдера и отправляемых данных. Подробнее: [local-first](local-first.md).

## 2. Завершённая диктовка не теряется

Распознанный результат сохраняется до подтверждённой доставки или осознанного удаления пользователем. Ошибка фокуса, вставки, cleanup или UI не имеет права уничтожить raw transcript. Инвариант MVP: 0 безвозвратно потерянных результатов на 100 завершённых диктовок.

## 3. Продукт улучшает форму, но не присваивает намерение

Meaning-preserving cleanup включён по умолчанию, однако raw transcript остаётся доступным. Существенная переформулировка, оптимизация промпта и изменение смысла выполняются только по явной команде пользователя.

## 4. Результат — текст в нужном приложении, а не успешный ASR

Транскрипция считается успешно завершённой только когда текст доставлен в ожидаемое поле либо безопасно оказался в recovery. Качество модели не компенсирует ненадёжную Windows-вставку.

## 5. Проактивность отвечает за безопасность и готовность, не за авторство

Приложение само подготавливает модель, обнаруживает конфликт hotkey, показывает состояние, сохраняет результат при сбое и предлагает восстановление. Оно не включает микрофон, не отправляет текст и не меняет намерение пользователя без инициированного им действия. Подробнее: [границы проактивности](proactive.md).

## 6. Один золотой workflow важнее ширины продукта

До доказательства цикла `hold → speak → release → clean → paste/recover` не добавляются meeting assistant, voice OS, агентные действия, macOS-порт, непрерывная диктовка и скрытая prompt optimization.

## 7. Модели заменяемы, решения принимаются по измерениям

Whisper и GigaAM подключаются через единый adapter boundary. Первый движок выбирается по локальному benchmark; название модели не становится продуктовой архитектурой или маркетинговым обещанием.

## 8. Наблюдаемость без слежки

Локальные структурированные метрики объясняют задержку, runtime, путь вставки и причину отказа, но по умолчанию не сохраняют аудио и содержимое диктовок в технических логах. Экспорт диагностики выполняется пользователем после предварительного просмотра.

## Проверка решений

Новое решение принимается, только если оно не нарушает жёсткую иерархию: **надёжность → точность → задержка → эффективность ресурсов**. При конфликте принципов приоритет получает сохранность результата и намерения пользователя.
